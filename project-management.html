Module 4

Project Management Brief

This brief demonstrates how I approach project planning, scope, responsibilities, risk, communication, and changes to project timelines.

Project Overview

Software Tracking Database

This project focused on planning the development of a software tracking database. The goal was to create a structured system that could support accurate software records, improve visibility, and prepare the organization for an upcoming audit.

The project required careful planning across multiple phases, clear ownership of responsibilities, defined deliverables, and attention to scope and project boundaries.

Project Plan

Six-Phase Approach

Phase 1

Requirements & Scope

Identify project goals, stakeholders, system requirements, project boundaries, and expected outcomes.

Phase 2

Data Review

Review current software records, identify missing information, and determine what data needs to be cleaned or migrated.

Phase 3

Database Design

Design the database structure, define fields and relationships, and make sure the system supports accurate reporting.

Phase 4

Development & Testing

Build the database, test functionality, validate records, and correct errors before implementation.

Phase 5

Implementation

Deploy the new system, transfer required data, and make sure users understand the new process.

Phase 6

Review & Handoff

Confirm that project requirements are met, document the system, and prepare the final deliverables for ongoing use.

Scope

Project Boundaries

The project scope included organizing software records, improving the accuracy of tracking information, designing the database structure, testing the system, and preparing documentation.

Items outside the project scope included unrelated technology upgrades, replacing systems that did not support the software tracking process, and taking on additional work that was not connected to the audit goal.

Project Change

Responding to New Constraints

During the project, the audit deadline was moved forward by two months and the project sponsor left the organization. These changes created additional schedule and communication risks.

To respond, I would re-prioritize the project around audit-critical deliverables, identify a new decision-maker, shorten review cycles, increase communication frequency, and delay lower-priority features that were not necessary for the audit.

This approach helps protect the project’s main objective while keeping stakeholders informed about tradeoffs and changes to the original plan.

What This Demonstrates

Project Management Skills

This project demonstrates my ability to break a larger problem into manageable phases, define scope, assign responsibilities, anticipate risks, and adjust when project conditions change.

These skills are valuable in data, technology, consulting, and software projects where teams must balance deadlines, stakeholder needs, technical requirements, and changing priorities.
